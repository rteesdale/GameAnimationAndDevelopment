# Studio Level 5: Director - Showcase Studio Instruction Manual

## Purpose

This manual is the Studio Level 5: Director pathway. It is designed to support students who may be preparing for or interested in CAPE Animation and Game Design. Students produce a CAPE-style 2D interactive game and supporting documentation: pitch, production bible elements, game design document, storyboard, UI plan, playtest evidence, asset credits, and reflection.

The final product is a polished 2D interactive game demo in Godot aligned to CAPE Unit 2 expectations.

## Module Identity

| Item | Description |
|---|---|
| Studio level | Studio Level 5: Director |
| Module name | Showcase Studio |
| Recommended length | 16-18 lessons plus public showcase |
| Session length | 60-120 minutes |
| Engine | Godot, 2D |
| Main project | CAPE-style 2D interactive game |
| Production style | Individual or small-team studio |
| CAPE bridge | Unit 1 Production Bible and Unit 2 2D Interactive Game |

## CAPE Alignment Summary

| CAPE Area | Senior Treatment |
|---|---|
| Unit 1 Module 1 | Pitch, production plan, demographics, SWOT, competitive advantage, IP, tools |
| Unit 1 Module 2 | Concept art, layout, levels, Caribbean/cultural relevance |
| Unit 1 Module 3 | Synopsis, story arc, character turnaround, environment/assets, production bible |
| Unit 2 Module 1 | Interactive design, UI wireframes, UX, audience, culture, ethical business practice |
| Unit 2 Module 2 | Three-level game, mechanics, goals, camera views, constraints, playtesting |
| Unit 2 Module 3 | Animated 2D assets, sound, animation principles, game-ready visual polish |

## Final Game Specification

| Feature | Requirement |
|---|---|
| Opening screen | Title, start, help/instructions |
| Gameplay | Complete 2D interactive game loop |
| Levels | Three levels or three clearly distinct stages |
| Game progression | Score/objectives, level transitions, win/lose states |
| Controls | Clear, appropriate, responsive |
| UX | Easy start, readable UI, feedback, accessibility consideration |
| Animation | Animated player, object, hazard, or environmental asset |
| Sound | Music or sound effects used meaningfully |
| Asset design | Original or properly licensed/credited assets |
| Demo readiness | Runs reliably for presentation |
| Documentation | CAPE-style production packet |
| Pitch | 5-minute pitch/demo |

1. Concept note.
2. Synopsis/game summary.

4. Rationale.
5. Competitive advantage.
6. SWOT analysis.
7. Character designs/turnarounds.
8. Environment designs.

10. Feature list.
11. Mechanics and rules.
12. Level designs.
13. UI wireframes.
14. Production schedule.
15. Tools/platform justification.
16. Asset and licence credits.
17. Playtest evidence.

# Lesson 1: CAPE Assessment Lens

## Purpose

Students understand what a CAPE-style game submission must demonstrate.

## Learning Outcomes

Students can:

1. Explain the difference between a fun prototype and an assessable production.
2. Identify evidence needed for design, development, and reflection.
3. Create a personal project readiness checklist.

## Discussion

Ask:

1. What makes a game playable?
2. What makes a game presentable?
3. What makes a game assessable?
4. What evidence proves design thinking?

Students create a checklist:


# Lesson 6: UI/UX And Wireframes

## Purpose

Students plan and build user interface with CAPE interaction principles.

## Required Wireframes

1. Opening screen.
2. Help/instructions.
3. In-game HUD.
4. Pause/restart if used.
5. Win screen.
6. Lose screen.

## UX Principles

| Principle | Evidence |
|---|---|
| Consistent | Same labels/colours used predictably |
| Perceivable | Text and icons readable |
| Learnable | Player can start quickly |
| Predictable | Controls and outcomes make sense |
| Feedback | Actions produce visible/audible response |

## Feedback Questions

1. Can a new player start unaided?
2. What does the HUD prioritize?
3. Is any information unnecessary?
4. What feedback is immediate?

# Lesson 7: Production Schedule And Risk

## Purpose

Students create a realistic production schedule and risk plan.

## Schedule Template

| Week | Goal | Evidence | Risk |
|---|---|---|---|
| 1 | Core prototype | Movement/objective | Scope too large |
| 2 | Level 1 | Playable level | Mechanics unclear |
| 3 | Level 2 | Progression | Bugs |
| 4 | Level 3 | Complete loop | Time |
| 5 | UI/audio/animation | Polish | Assets |
| 6 | Playtest/revision | Test notes | Stability |
| 7 | Pitch/docs | Final packet | Missing evidence |

## Feedback Questions

1. What is the first playable milestone?
2. What is the biggest risk?
3. What can be cut?
4. What must not be cut?

# Lesson 8: Godot Prototype Sprint

## Purpose

Students build the minimum playable version.

## Minimum Prototype

1. Player moves.
2. One objective works.
3. One hazard/challenge works.
4. Score/progress changes.
5. Win/lose or end condition exists.

## Sprint Rule

No polish until the loop works.

## Feedback Questions

1. Is the core loop playable?
2. What is missing from the loop?
3. What is the highest-risk mechanic?
4. What should be tested first?

# Lesson 11: Playtest 1 - Usability

## Focus

1. Can players start?
2. Are controls clear?
3. Is objective clear?
4. Is UI readable?
5. Does feedback make sense?

## Evidence

Students collect:

1. Tester names.
2. Observed confusion.
3. Quotes or paraphrased feedback.
4. Planned revisions.

# Lesson 12: Playtest 2 - Balance And Progression

## Focus

1. Difficulty curve.
2. Level progression.
3. Scoring or objectives.
4. Win/lose reliability.
5. Replay value.

## Feedback Questions

1. Where did players fail?
2. Was failure fair?
3. Did players improve?
4. What should be adjusted?

# Lesson 13: Playtest 3 - Presentation Readiness

## Focus

1. Does the game run reliably?
2. Can it be demonstrated in 2-3 minutes?
3. Are instructions and end states clear?
4. Are there visible bugs?
5. Is documentation aligned with final game?

# Lesson 15: Pitch Preparation

## Purpose

Students prepare a 5-minute pitch and demo.

## Pitch Structure

```text
1. Hook and title
2. Target audience and rationale
3. Gameplay synopsis
4. Character/environment
5. Mechanics and progression
6. Demo
7. Playtest revision
8. Competitive advantage
9. Closing statement
```

## Feedback Questions

1. Is the opening strong?
2. Is the demo reliable?
3. Is the pitch within time?
4. Does the speaker explain design decisions?

# Final Assessment Rubric

| Area | 4 - Strong | 3 - Secure | 2 - Developing | 1 - Beginning |
|---|---|---|---|---|
| Concept/rationale | Clear, focused, audience-aware | Mostly clear | Partly clear | Weak |
| Game functionality | Polished playable CAPE-style demo | Mostly playable | Partially playable | Not playable |
| Levels/progression | Strong three-stage progression | Mostly clear | Weak | Missing |
| Mechanics | Integrated, understandable, balanced | Mostly working | Some working | Minimal |
| UI/UX | Clear, accessible, helpful | Mostly clear | Inconsistent | Missing |
| Animation/sound | Purposeful and polished | Present | Limited | Missing |
| Documentation | Complete CAPE-style packet | Mostly complete | Incomplete | Minimal |
| Playtesting | Strong evidence and revisions | Some evidence | Limited | None |
| Ethics/IP | Clear crediting and suitability | Mostly clear | Some gaps | Missing |
| Pitch/demo | Confident, timed, persuasive | Mostly clear | Limited | Missing |

## Minimum Completion Definition

A Studio Level 5: Director project is complete when:

1. It runs as a polished 2D interactive game demo.
2. It includes opening/help, gameplay, progression, and ending.
3. It has three levels or stages.
4. It includes animation and sound feedback.
5. It includes a CAPE-style documentation packet.
6. It includes playtest evidence and revision.
7. It can be pitched and demonstrated in 5 minutes.
